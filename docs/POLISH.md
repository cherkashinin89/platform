# POLISH — баги, стиль, UX, техдолг

Актуально на: 2026-10-29.

## Правило «заметил — записал»

Во время сессии, если замечена ошибка или несоответствие визуальному стилю — **сразу** фиксируем здесь, не откладывая. Ассистент записывает по ходу; в конце сессии — сводка добавленного на подтверждение.

Типы:
- `bug` — не работает / падает / неверный результат.
- `style` — расхождение с визуальным стилем (отступы, цвета, шрифты, иконки, адаптив).
- `ux` — неудобно / непонятно / нет обратной связи.
- `debt` — устаревший код, дубли, TODO.

Не сюда: «мелкие улучшения» (nice-to-have) → `BACKLOG.md` со статусом `idea`.

## Формат записи

```
### Pn — [тип] Краткое название
- Где: сервис / URL / файл
- Когда: YYYY-MM-DD
- Приоритет: высокий / средний / низкий
- Статус: open / fixed (дата, коммит)
- Детали: шаги воспроизведения, ожидание/факт (если нужно)
```

## Этап полировки

Обработка — по запросу пользователя. Порядок: приоритет → дата. После фикса — статус `fixed` + дата/коммит, запись **не удаляем** (чтобы видеть, что уже чинили). В `HISTORY.md` — одна сводная строка «полировка (дата): P3, P7 … исправлены».
