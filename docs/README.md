# Документация platform — точка входа

Актуально на: 2026-10-29.

Этот файл — навигация по документации и правила работы. При конфликте правил —
главный этот файл; при конфликте описания системы — `SPEC.md`.

## 1. Оглавление

| Файл | Что внутри | Когда читать |
|---|---|---|
| `SPEC.md` | «Как есть»: сервисы, модели, эндпоинты (обзор), конфиг, деплой, безопасность | Понять устройство системы |
| `HISTORY.md` | История изменений: по задачам, ссылки на `tasks/`, вехи | Узнать «почему так» и «когда появилось» |
| `BACKLOG.md` | Незакрытые ТЗ: `planned` / `deferred` / `idea` | Выбрать следующую задачу |
| `POLISH.md` | Баги, стиль, UX, техдолг (правило «заметил — записал») | Этап полировки |
| `routes.md` | Реестр эндпоинтов (генерируется, не править руками) | Найти маршрут/эндпоинт |
| `tasks/Wxx.md` | Детали по конкретным задачам (эндпоинты, файлы, нюансы) | Глубокая работа по задаче |

Обзор проекта и установка — в корневом `README.md`.

## 2. Как начать сессию

1. Прочитать этот файл (правила ниже).
2. Прочитать `SPEC.md` — что есть сейчас.
3. Взять задачу из `BACKLOG.md` или из запроса пользователя; детали — в `tasks/Wxx.md`.

## 3. Правила работы

- **Один шаг — одно действие.** Проверка → действие → проверка.
- **Не коммитить без проверки.** Сначала синтаксис/поведение, потом коммит.
- **Бэкап БД перед критичными правками** (миграции, массовые UPDATE/DELETE):
  `pg_dump "$DATABASE_URL" -Fc -f ~/backups/platform_$(date +%Y%m%d_%H%M%S).dump`.
- **Комментарии — на русском.**
- **`sed -n 'N,Mp'` — только с числами** (без диапазонов-выражений).
- **Не дублировать:** SPEC — «что и зачем», `tasks/` — «как именно».
- **«Заметил — записал»:** баг, расхождение со стилем, UX-шероховатость, техдолг —
  сразу в `POLISH.md` (см. инструкцию там). В конце сессии — сводка добавленного на подтверждение.

## 4. Формат работы с терминалом

1. **Одна команда — один шаг.** Дал команду → дождись вывода → проверь → следующий шаг. Не давай пачку команд «на всё сразу».
2. **Короткие команды.** Без длинных heredoc (`cat << EOF` на 50+ строк). Сложное (многострочный Python, шаблоны) — через временный файл: `python3 /tmp/xxx.py`, потом запуск.
3. **Не ломать кавычки.** Внутри двойных кавычек `"..."` не использовать обратные кавычки (`` ` ``) — терминал выполнит их как команду. Для сложного экранирования — одинарные кавычки снаружи или временный файл.
4. **Проверка после действия.** После записи файла/правки — синтаксис (`python -c "import ast..."`), после рестарта — `systemctl is-active`, после маршрута — `curl -w "%{http_code}"`.
5. **Показывать вывод.** Пользователь вставляет вывод команды — ассистент по нему решает следующий шаг, не додумывает.
6. **Осторожно с `sed -i` и regex** в кириллице/спецсимволах — предпочитать Python-скрипты для правок текста.
7. **Разрушительное — отдельно.** Удаление файлов, `rm -rf`, `git reset`, миграции БД — отдельным шагом, с предварительной проверкой и (для БД) бэкапом.

## 5. Чек-лист закрытия сессии

1. Перегенерировать реестр маршрутов (если менялись эндпоинты):
   `python deploy/gen_routes.py`.
2. Сводка добавленного в `POLISH.md` — на подтверждение пользователю.
3. Обновить `HISTORY.md` (закрытые задачи) и `BACKLOG.md` (новые/закрытые) при необходимости.
4. Коммит после проверки (осмысленное сообщение, русский).

## 6. Полезные команды

**Сервисы:**

```bash
sudo systemctl restart framework cloud      # перезапуск
systemctl is-active framework cloud         # статус
journalctl -u framework -n 50 --no-pager    # логи framework
journalctl -u cloud -n 50 --no-pager        # логи cloud
```

**Миграции (из venv framework):**

```bash
cd ~/apps/platform/framework && source venv/bin/activate
flask db revision --autogenerate -m "описание"   # сгенерировать
flask db upgrade                                  # применить
```

**Бэкап БД:**

```bash
cd ~/apps/platform
set -a; . ./.env; set +a
pg_dump "$DATABASE_URL" -Fc -f ~/backups/platform_$(date +%Y%m%d_%H%M%S).dump
```

**Nginx / Collabora:**

```bash
sudo nginx -t && sudo systemctl reload nginx
cd ~/apps/platform/collabora && sudo docker compose up -d
```

**Реестр маршрутов:**

```bash
cd ~/apps/platform && python deploy/gen_routes.py
```
