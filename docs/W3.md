# W3 — Прикрепление файлов и папок облака к статьям и страницам

**Версия:** финал (после обсуждения и проверок кода 1–7)
**Дата:** 2026-10-10
**Статус:** ТЗ зафиксировано, готово к реализации

---

## 1. Цель

Дать автору статей и страниц возможность **прикреплять файлы и папки из своего облака** к тексту. Прикрепление равносильно **созданию публичной шары** (`CloudShare`). На публичной странице файлы/папки отображаются плитками, папки — открываются в контексте статьи (AJAX), с возможностью навигации.

---

## 2. Модели БД

### 2.1. Новая таблица `ShareAttach`

Полиморфная M2M-связь между `CloudShare` и `Article` / `Page`.

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | Integer, PK | |
| `share_id` | FK → `CloudShare.id`, `ondelete='CASCADE'` | NOT NULL, index |
| `target_type` | String(20) | NOT NULL, `CHECK IN ('article', 'page')` |
| `target_id` | Integer | NOT NULL, index |
| `created_at` | DateTime | default=utcnow |

**Индексы:**
- `idx_share_attach_share` — по `share_id`.
- `idx_share_attach_target` — составной по `(target_type, target_id)`.

**Логика:**
- Одна строка = одна связь шары с сущностью.
- Одна шара → много строк (M2M).
- `target_type` — строка (`'article'` / `'page'`).
- `target_id` — id статьи или страницы.
- При удалении шары — строки удаляются каскадно (FK).
- При удалении статьи/страницы — удаляются строки в коде (полиморфизм).

### 2.2. `CloudShare` — без изменений

Уже есть: `id`, `file_id`, `token`, `created_by_id`, `created_at`, `expires_at`, `password_hash`, `download_count`, `max_downloads`.

### 2.3. Миграция

- Создать таблицу `share_attach`.
- Не трогать `cloud_share`.

## 3. API

### 3.1. framework

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/admin/api/cloud-tree` | Дерево папок пользователя (для модалки) |
| GET | `/admin/api/cloud-folder/<id>` | Содержимое папки (JSON: folders + files) |
| GET | `/admin/api/cloud-files` | **расширить:** добавить `is_folder`, `parent_id`; убрать `owner_name` для редактора |
| POST | `/admin/api/attach-to-article` | Создать шары через облако + `ShareAttach` |
| GET | `/admin/api/check-attachments/<file_id>` | Проверка привязок (для предупреждения) |
| GET | `/article/<id>/folder/<folder_id>` | AJAX-фрагмент содержимого папки (анонимно) |

**`/admin/api/attach-to-article`** — принимает JSON `{article_id: 3, file_ids: [8, 12, 15]}`.
Ответ — JSON `{ok: true, attachments: [{share_id, token, path, file_id, file_name, is_folder}, ...]}`.

### 3.2. cloud

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/internal-share/<file_id>` | Создать/переиспользовать шару (с X-Internal-Key) |

**Авторизация:**
- `X-Internal-Key: <INTERNAL_API_KEY>` — сверяется с `.env`.
- `X-User-Id: <id>` — от имени кого создавать.
- Если ключ не совпал → 403.

**Ответ:** тот же, что у `/api/share/<id>`.

## 4. UI модалки

### 4.1. Лэйаут

**Двухпанельный**, **адаптивный** (min 800px, max 95% экрана):
- Слева — дерево папок.
- Справа — рабочая область (плитки + счётчик).
- Внизу — кнопка «Прикрепить (N)» + крестик вверху справа.

### 4.2. Дерево

- Корень — `Мои файлы`.
- Иерархия — как в Яндекс.Диске (плоское, раскрывающееся).
- Изначально — всё свёрнуто, кроме корня.
- При клике по папке — раскрывается до активной папки.
- `sessionStorage` — для `expandedIds`.
- Данные — `/admin/api/cloud-tree`.

### 4.3. Рабочая область

**Плитки** как в Яндекс.Диске:
- Миниатюра (для картинок — оригинал с CSS-ограничением `max-width: 200px`; миниатюры — отдельная задача).
- Иконка (Bootstrap Icons по типу) — для документов.
- Иконка папки — для папок.
- Имя + размер.
- Чекбокс в углу: серый полупрозрачный → яркий при наведении → цветной при отметке.

**Клик:**
- По файлу (имя/превью) — выбрать (toggle).
- По папке (имя/превью) — войти внутрь.
- По чекбоксу — выбрать.

**Лайтбокс в модалке — НЕТ.**

### 4.4. Счётчик и кнопки

- `Выбрано: N из M`.
- `Выбрать все` / `Снять все`.

### 4.5. Нижняя панель

- Кнопка `Прикрепить (N)` — активна, если N > 0.
- Крестик вверху справа — закрыть без прикрепления.

### 4.6. Состояния

- Пустое облако — сообщение + ссылка на облако.
- Пустая папка — `Папка пуста`.
- Загрузка — `Загрузка…`.
- Ошибка — `Ошибка загрузки` + retry.

### 4.7. Ограничения

- Источник — **только облако** (вкладка `uploads` убрана; раздел `Файлы` в админке остаётся как есть).
- Чьи файлы — только свои (`owner_id = current_user.id`).
- Фильтр по владельцу — убираем.
- Загрузка файлов из модалки — убираем.
- Лимит — без лимита, но предупреждение при выборе > 20.

### 4.8. Реализация

- Свой оверлей (не Bootstrap modal).
- CSS — в `core/static/css/style.css`.
- JS — в `core/static/js/attached-files.js`.
- Шаблон — в `core/templates/partials/file_manager_modal.html`.

## 5. UI статьи / страницы

### 5.1. Формат плитки

**Документы:** `<a href="/s/<token>" class="attached-file attached-file-doc"><i class="bi bi-file-pdf"></i> имя.pdf <small>2.5 МБ</small></a>`.

**Папки:** `<a href="#" class="attached-file attached-file-folder" data-share-token="..." data-is-folder="true"><i class="bi bi-folder-fill"></i> имя_папки</a>`.

**Картинки:** `<a href="/s/<token>" class="attached-file attached-file-image"><img src="/media/<id>" alt="имя"></a>`.

### 5.2. Два состояния плитки

**До сохранения (в редакторе):**
- Класс `is-temp` (жёлтая рамка / серый фон).
- `data-file-id="42"`.
- Иконка/миниатюра, имя, размер.

**После сохранения:**
- Без `is-temp`.
- `data-share-token="abc..."`.
- `href="/s/abc..."`.

### 5.3. Открытие папки (AJAX)

- **API:** `GET /article/<id>/folder/<folder_id>` (framework, анонимно).
- **Проверка:** статья публична + папка привязана к статье через `ShareAttach` + `_is_descendant_of`.
- **Что отдаёт:** HTML-фрагмент (Jinja, `core/templates/partials/folder_view.html`).
- **Как показывать:** замена текста статьи фрагментом (`display: none` для текста).
- **Кнопка «Назад»** — в родительскую папку.
- **Кнопка «Крестик»** — вернуть текст статьи.
- **Заголовок сверху:** «Папка: <имя>».
- **Хлебных крошек нет.**
- **URL не меняется.**
- **Пагинация:** «Показать ещё» (по 50 файлов).

### 5.4. Логика клика по файлу

- Картинка → лайтбокс.
- Документ → скачать.
- Удалённый/недоступный файл → серая иконка + `(недоступно)`, клик → toast «Файл недоступен».

### 5.5. Читатель не видит владельца

В статье — только плитка (иконка/миниатюра, имя, размер). Без «Файл от <username>».

## 6. Логика сохранения

### 6.1. При сохранении статьи

1. Парсим HTML.
2. Собираем `data-share-token` (существующие шары).
3. Собираем `data-file-id` (новые файлы).
4. Для каждого `data-file-id` — `POST /api/internal-share/<file_id>` (через X-Internal-Key).
5. Заменяем `data-file-id` → `data-share-token`, убираем `is-temp`.
6. Создаём `ShareAttach` для новых связей.
7. Удаляем `ShareAttach` для шар, чьи `token` не найдены в HTML.
8. Удаляем `CloudShare`, если нет других `ShareAttach`.
9. Сохраняем статью.

### 6.2. При удалении статьи

1. Находим все `ShareAttach` с `target_type='article'`, `target_id=<article_id>`.
2. Удаляем их.
3. Для каждой шары: если нет других `ShareAttach` — удаляем `CloudShare`.

### 6.3. При копировании статьи

1. Копия создаётся со всем HTML.
2. Для каждого `data-share-token` в HTML — создаём `ShareAttach` для копии.
3. Шары — те же (не дублируются).

### 6.4. При trash файла в облаке

- Перед trash — framework проверяет `ShareAttach` для файла.
- Если есть привязки — предупреждение пользователю со списком статей/страниц.
- Пользователь подтверждает → trash → шары удаляются (текущее поведение облака).
- Статьи: плитки становятся `(недоступно)`.
- **Задача W38+W39.**

### 6.5. При восстановлении из корзины

- Шары не восстанавливаются. Пользователь прикрепляет заново.

## 9. Спорные места — закрыты

| Вопрос | Решение |
|---|---|
| Вкладка uploads для админа | Убрать из модалки, оставить раздел в админке |
| Файл чужого пользователя | Только свои (редактор видит только свои) |
| Статья удалена, шара в другой статье | Шара не удаляется (есть другие ShareAttach) |
| owner_id в ShareAttach | Нет (владелец — в CloudShare) |
| Формат миниатюр | Оригинал с CSS (миниатюры — отдельная задача) |
| Размер файла | Из CloudFile.size через human_size() |
| CloudFile не найден | Рендер как `(недоступно)` + лог |
| ShareAttach без CloudShare | Игнорировать + лог (не должно случаться) |
| Кэш браузера | no-cache |
| Состояние папки между открытиями | Не сохраняется |
| F5 с открытой папкой | Страница перезагружается, папка закрыта |
