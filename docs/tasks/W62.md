# W62 — Продажа билетов (Яндекс, Пушкинская карта)

**Дата:** 2026-11-03
**Статус:** запланировано (ожидает договора с Яндексом и спецификации Yaga)
**Приоритет:** средний
**Связано:** W60 (медиаредактор), W25 (альбомы), PRO.Культура.

---

## 1. ЦЕЛЬ

Продажа билетов на концерты (ДК с концертным залом) через свой сайт, с поддержкой Пушкинской карты. Интеграция с Яндексом (билетный оператор) по протоколу Yaga. Персональные данные покупателей не храним; нужна статистика купленных/погашенных билетов.

---

## 2. ОРГАНИЗАЦИОННЫЙ ЭТАП (вне кода)

1. Заключить договор с Яндексом (Яндекс Афиша).
2. Получить полную спецификацию протокола Yaga (закрытая, после договора).
3. Уточнить в договоре: кто передаёт данные о гашении в реестр Пушкинской карты (Яндекс или мы через их API).
4. События на PRO.Культуре: привязка к Яндекс Афише как оператору.
5. «Белый» терминал (если нужен) — уточнить у Яндекса.

**Важно:** без спецификации Yaga модели данных — черновые (уточним после API).

---

## 3. МОДЕЛИ ДАННЫХ (ЧЕРНОВИК — уточнить после Yaga)

- **Event** — событие/концерт: title, description, poster (файл облака), pro_culture_id (ID на PRO.Культуре), is_published, created_at.
- **Session** — сеанс: event_id, starts_at, hall (зал), yandex_session_id (ID сеанса в Яндексе).
- **Seat** — место: hall/row/number (или схема зала).
- **Order** — заказ: yandex_order_id, session_id, status (pending/paid/cancelled), total, created_at.
- **Ticket** — билет: order_id, barcode (уникальный), seat_info (ряд/место), price, status (sold/used/returned), used_at.

**Связь с PRO.Культурой:** в `reserve` передаётся `integrations: [{sourceName: "pro-culture", sourceId: <pro_culture_id>}]`.
**Пушкинская карта:** в `reserve` — `loyaltyPrograms: [{type: "pushkin-card"}]`.

**Персональные данные:** не храним (только order_id, barcode, места).

---

## 4. ИНТЕГРАЦИЯ С ЯНДЕКСОМ (YAGA) — уточнить по спецификации

- `sessions` — список сеансов.
- `available-seats` — доступные места.
- `reserve` — бронь (loyaltyPrograms, integrations).
- `confirm` — подтверждение оплаты (выпуск билетов; сохраняем Order/Ticket).
- Возврат/отмена — (уточнить).

**Клиент:** адаптер в framework (requests), конфиг (API-ключи, URL) — в SiteSettings/.env.

---

## 5. МОДУЛЬ КОНТРОЛЯ (ПОГАШЕНИЕ)

- Веб-страница контролёра (мобильная): `/admin/checkin` — ввод/сканирование barcode → найти Ticket → «Погасить» (status=used, used_at).
- Отчёты: куплено/погашено по сеансу (для статистики).
- Передача гашения в реестр: **уточнить в договоре** (Яндекс или мы через их API). Пока — только своя БД.
- В будущем — мобильное приложение (нативная камера/сканер). Пока — веб (камера браузера).
