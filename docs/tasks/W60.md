# W60 — Медиаредактор Redactix (замена TinyMCE для статей/страниц)

**Дата:** 2026-10-29
**Статус:** запланировано
**Приоритет:** средний
**Связано:** W3 (заменено W58), W47 (почта), W48 (Collabora), W58 (X-Accel), W59 (просмотр).

---

## 1. ЦЕЛЬ

Заменить TinyMCE на Redactix для статей и страниц: медиаредактор с блоками (текст, изображения, галерея, видео, embed, документы), простой для «слабого пользователя».

Задачи:
- Убрать «жёсткую привязку к строке»; вставка медиа — отдельными блоками.
- Фото: миниатюры с лайтбоксом (использовать существующий лайтбокс проекта).
- Видео: HTML5-плеер и embed (YouTube, VK, Vimeo и т.д.).
- Документы: список плитками (из облака).
- Убрать отдельный блок «альбомы под статьёй» — заменить галереей внутри контента.
- Сохранить привязку файлов к облаку (ContentFile, W58) — при сохранении статьи регистрировать использованные файлы.

---

## 2. ЧТО УЖЕ ЕСТЬ (БАЗА)

- **TinyMCE** — текущий редактор статей/страниц (framework/static/tinymce). Для почты (W47) остаётся.
- **Облако**: CloudFile, ContentFile (W58), /files/<id> (X-Accel), internal API (X-Internal-Key).
- **Лайтбокс**: самописный, core/templates/core_base.html (блок lightbox) + триггеры data-lightbox; навигация prev/next.
- **Альбомы под статьёй**: отдельный блок в article.html (Photo/Album) — переделать в галерею внутри контента.
- **Просмотр офисных файлов**: /view/<id> (W59), Collabora (W48).

---

## 3. РАЗВЕДКА (факты)

Проведена 2026-10-29 на тестовой странице /admin/redactix-test.

- Redactix подключён в vanilla JS (ES-модуль), без React; заводится в окружении проекта, ошибок в консоли нет.
- Модули: Image, Gallery, Video, Embed (в ядре). Блоки работают.
- **HTML на выходе — семантический**:
  - текст: `<p>...</p>`;
  - видео: `<figure class="redactix-video" data-aspect="16:9"><video src="..." controls></video></figure>`;
  - embed: `<figure class="redactix-embed">...<iframe ...></iframe>...</figure>`;
  - изображение: `<img src="..." ...>` (в галерее — свой контейнер).
- **Лайтбокса в Redactix нет** — использовать существующий (data-lightbox).
- **Загрузка с компьютера** без uploadUrl не работает (только URL). Нужен адаптер к облаку.
- Модель Article.content/Page.content остаётся Text (HTML) — без миграции под JSON.

## 4. АРХИТЕКТУРА ИНТЕГРАЦИИ

### 4.1. Адаптер загрузки (framework → cloud)

Redactix требует от эндпоинта загрузки JSON-формат: `success, src, srcset, alt, title, caption`.

В framework — два маршрута-адаптера (только admin/editor):
- `POST /admin/redactix/upload` — принимает файл, передаёт в cloud (internal API, X-Internal-Key), возвращает JSON для Redactix.
- `GET /admin/redactix/browse` — список файлов облака (для галереи Redactix), в формате, который ждёт редактор.

Проксирование — по образцу `/api/internal-share` (W3/W58): заголовки X-Internal-Key, X-User-Id.

### 4.2. Парсинг контента при сохранении

При сохранении статьи/страницы framework парсит HTML и находит: `<img src>`, `<video src>`, `<a href>` на файлы облака.
Найденные файлы регистрируются в ContentFile (W58) и/или FileUsage — через существующий content_service.

### 4.3. Рендер на публичной части

Article.content/Page.content остаётся Text (HTML). На публичной части — `content|safe` + CSS для блоков Redactix (figure.redactix-video, figure.redactix-embed и т.д.).

---

## 5. ЛАЙТБОКС

Использовать существующий лайтбокс проекта (core/templates/core_base.html, блок lightbox; триггеры data-lightbox).

- В галерее Redactix при рендере проставлять на ссылки изображений `data-lightbox` и `data-full` (URL оригинала).
- На публичной странице статьи лайтбокс уже подключён через core_base — проверить, что блок галереи его подхватывает.
- Не добавлять сторонние лайтбокс-библиотеки.

---

## 6. ДОКУМЕНТЫ ПЛИТКАМИ

В Redactix нет готового блока для списка документов. Варианты:
- **Кастомный блок (предпочтительно):** плагин Redactix (vanilla JS) — плитки файлов, данные из облака (browse).
- **Raw HTML:** только для продвинутых, не для «слабого пользователя».

Решение: кастомный блок в рамках W60 (или отдельной подзадачей, если объём велик).

---

## 7. МИГРАЦИЯ И СОВМЕСТИМОСТЬ

- Старые статьи/страницы (HTML от TinyMCE) остаются как есть (content — HTML).
- Новые — Redactix. Двойной режим не нужен: контент — просто HTML.
- TinyMCE остаётся для почты (compose, W47); для статей/страниц — убирается.
- Отдельный блок альбомов под статьёй убирается после внедрения галереи Redactix.

## 8. ЭТАПЫ И ОЦЕНКА

1. Адаптер upload/browse (framework → cloud) — 2–3 дня.
2. Внедрение Redactix в формы Article/Page — 2–3 дня.
3. Парсинг HTML при сохранении (ContentFile/FileUsage) — 1–2 дня.
4. Галерея + лайтбокс (data-lightbox) — 1–2 дня.
5. Кастомный блок «Документы плитками» — 3–5 дней.
6. Удаление блока альбомов под статьёй — 1 день.
7. Полировка (стили, адаптив), тесты — 2–3 дня.

Итого: ~2 недели плотной работы (без форс-мажоров).

---

## 9. РИСКИ И ОГРАНИЧЕНИЯ

- Redactix — молодой проект (меньше пользователей); код открыт, можно допиливать.
- Зависимость от стороннего API (upload/browse) — стабильность форматов.
- Кастомный блок документов требует написания плагина (vanilla JS).
- TinyMCE остаётся в проекте (для почты) — дублирование библиотек (не критично).
