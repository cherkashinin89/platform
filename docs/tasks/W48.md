# W48 — Совместное редактирование файлов (Collabora Online)

**Дата:** 2026-10-15 (обновлено 2026-10-26)
**Статус:** ✅ v1 завершён (2026-10-28). Этапы 1–5 (кроме UI соавторов и «Сохранить как» — убрано). Реализовано: docx/xlsx/pptx, `can_edit`, история версий, `/collabora`, `/view/<id>` (read-only).
**Приоритет:** средний

## ЦЕЛЬ

Возможность редактировать файлы облака **в браузере** через Collabora Online,
без скачивания и локальных редакторов. Автор шарит файл — получатели открывают
ссылку и редактируют онлайн. Конфликты снимаются самой Collabora (OT).

**Не входит в v1:**
- UI совместного присутствия (соавторы, курсоры, аватарки) — позже.
- Пароль/срок/лимит шары — это W35, отдельно.
- Совместное редактирование в реальном времени «как в Яндекс.Документах»
  с индикацией присутствия — позже, после базовой интеграции.

## РЕШЕНИЯ (согласовано)

1. **Движок:** Collabora Online (CODE), Docker-контейнер, ~1,5 ГБ RAM.
   OnlyOffice отклонён — требует ≥4 ГБ RAM, не влезает в 6 ГБ сервера.
2. **Форматы v1:** базовый минимум, наращивание по этапам (см. «Этапы»).
3. **Режим v1:** один пользователь, без UI совместного присутствия.
   Конфликты при одновременном открытии — Collabora решает сама (OT).
4. **Связь с W35:** W48 самодостаточен. В `CloudShare` добавляем только
   `can_edit`. Пароль/срок/лимит — W35, отдельно, позже. W35 не блокирует W48.
5. **Docker:** ставим Docker на сервер, Collabora — контейнер (официальный путь).

## АРХИТЕКТУРА

- **WOPI Host** = облачный сервис (Flask). Реализует конечные точки WOPI.
- **WOPI Client** = Collabora. Вызывает WOPI Host для чтения/записи файлов.
- **Своего движка редактирования не пишем.**
- Collabora рендерит документ в iframe, браузер собирает фрагменты (tiles).
- Сохранение: Collabora вызывает `PutFile` на WOPI Host при сохранении.
- Защита от конфликтов: заголовок `X-COOL-WOPI-Timestamp` → HTTP 409 +
  `{"COOLStatusCode": 1010}`, если время модификации не совпало.

**Ресурсы:**
- Collabora: ~1,5 ГБ RAM (1 ГБ + 50 МБ/одновременный пользователь).
- Docker: дополнительный компонент инфраструктуры, обновления образа,
  автозапуск при ребуте.

**Сетевая схема:**
- Collabora слушает `127.0.0.1:9980` (внутри Docker).
- Nginx (отдельный server-блок) проксирует `office.<домен>` → `127.0.0.1:9980`,
  с обязательной поддержкой WebSocket.
- Браузер → iframe на `office.<домен>` → Collabora → WOPI Host (облако).

## WOPI-ИНТЕРФЕЙС (облачный сервис, Flask)

Минимально необходимые конечные точки (v1):

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/wopi/files/<file_id>` | `CheckFileInfo` — имя, размер, права (`UserCanWrite`) |
| GET | `/wopi/files/<file_id>/contents` | `GetFile` — бинарное содержимое файла |
| POST | `/wopi/files/<file_id>/contents` | `PutFile` — приём изменённого содержимого |

**Детали:**
- `CheckFileInfo` возвращает минимум `BaseFileName`, `Size`,
  `UserCanWrite` (из `CloudShare.can_edit`).
- `GetFile` читает файл из `cloud_data/<uid>/<stored_name>`.
- `PutFile` пишет обратно в `cloud_data/<uid>/<stored_name>`,
  проверяет `X-COOL-WOPI-Timestamp` → 409 при расхождении.
- Авторизация: `access_token` (случайная строка), Collabora передаёт
  обратно в WOPI Host для проверки.
- `aliasgroup1` в конфиге Collabora = полный URL облачного сервиса.

## РИСКИ

1. **HDD:** Collabora активно пишет временные файлы (chroot-jail),
   HDD медленный — возможны тормоза при открытии/сохранении.
   Митигация: тестировать на реальном документе, при необходимости —
   перенести jail на tmpfs (RAM-диск).
2. **Docker на i3 M380:** работает, но образы занимают место на диске.
   Митигация: чистить старые образы (`docker image prune`).
3. **Совместимость docx:** Collabora (LibreOffice) может съехать на сложной
   вёрстке. Митигация: тесты на реальных документах, при критичных
   расхождениях — рассмотреть OnlyOffice позже (при апгрейде RAM).
4. **Мёртвые сессии:** если пользователь закрыл браузер, не сохранив —
   Collabora держит сессию. Митигация: таймаут в конфиге Collabora.
5. **Одновременное редактирование без UI присутствия:** пользователи
   не видят друг друга, но Collabora сливает изменения (OT). Возможны
   неожиданные правки «от другого». Митигация: в v1 предупредить в UI
   «документ могут редактировать другие», полный UI — Этап 5.
